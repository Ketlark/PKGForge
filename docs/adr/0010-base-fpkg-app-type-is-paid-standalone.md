# ADR 0010: Base fPKGs use paid standalone APP_TYPE

Date: 2026-06-13

## Status

Accepted

## Context

After fixing package installation, the PS4 launcher failed with `CE-39929-2`. PSDevWiki maps that error to `SCE_PROCESS_STARTER_ERROR_FREEMIUM_SKU_FLAG / 0x80A40053`, described as an unmatched freemium SKU flag.

PKG Forge inherited `APP_TYPE=4` from LibOrbisPkg's `DefaultGD` SFO template. LibOrbisPkg's own SFO enum labels that value as "Freemium app". The generated PS1 and PS2 fPKGs are base standalone applications, not freemium SKUs.

## Decision

PS1 and PS2 base fPKGs generated by PKG Forge set `APP_TYPE=1` in `param.sfo`, which means "Paid standalone full app".

PKG header `content_flags` remains `0x0A000000` for `pkg_ps4_app`, matching LibOrbisPkg's `Unk_x8000000 | GD_AC` flags.

## Consequences

The PS4 launcher no longer receives a freemium app type for base emulator packages. Changing this value also changes the serialized `param.sfo`, so PKG Forge must recalculate Param Digest, General Digests, body digest, and header signature after SFO finalization.

Tests now assert that PS1 and PS2 SFO generation uses `APP_TYPE=1`.

## Alternatives Considered

### Keep LibOrbisPkg DefaultGD unchanged

`APP_TYPE=4` matches the LibOrbisPkg default template, but it maps to Freemium app and triggered `CE-39929-2` at launch.

### Change PKG content flags instead

The PKG header flags already match LibOrbisPkg for `pkg_ps4_app`. Changing them would move away from the validated package layout without addressing the SFO app type mismatch.
